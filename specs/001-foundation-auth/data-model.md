# Data Model: 001 Foundation, Phone Sign-In, Devices, Profile & Contacts

PostgreSQL 16 (`postgres:16-trixie`), managed with Prisma migrations in the `api` repo.
All ids are UUIDv7 generated by the API. Timestamps are `timestamptz`.

## users

| Field | Type | Rules |
|---|---|---|
| id | uuid PK | |
| phone_e164 | text UNIQUE NOT NULL | valid E.164, `^\+[1-9]\d{6,14}$` |
| display_name | varchar(25) NULL | NULL until profile setup; 1–25 chars after trim |
| about | varchar(140) NOT NULL DEFAULT 'Hey there! I am using Chat App.' | 0–140 chars |
| avatar_key | text NULL | object key in `avatars` bucket |
| created_at, updated_at | timestamptz | |

A user with `display_name IS NULL` has `profileComplete = false`; clients force profile setup.

## devices

| Field | Type | Rules |
|---|---|---|
| id | uuid PK | later used as the Signal device address |
| user_id | uuid FK → users ON DELETE CASCADE | |
| type | enum `android` \| `web` | |
| name | varchar(64) NOT NULL | e.g. "Pixel 8", "Chrome on Windows" |
| created_at | timestamptz | |
| last_active_at | timestamptz | updated at most once a minute |
| revoked_at | timestamptz NULL | |
| revoked_reason | enum `signed_out` \| `replaced` \| `evicted` \| `token_reuse` \| `inactive` NULL | |

Indexes: `(user_id) WHERE revoked_at IS NULL`.
Invariants (enforced in the service inside a transaction with `SELECT … FOR UPDATE` on the user):
at most 1 active `android` and at most 4 active `web` devices per user.

**State**: `active` → `revoked` (terminal). A revoked device never becomes active again; signing
in again creates a new device row.

## sessions

| Field | Type | Rules |
|---|---|---|
| id | uuid PK | |
| device_id | uuid FK → devices ON DELETE CASCADE | |
| refresh_hash | char(64) UNIQUE | SHA-256 hex of the refresh token |
| expires_at | timestamptz | now + 30 days on every rotation |
| rotated_at | timestamptz NULL | set when replaced by a newer session |
| created_at | timestamptz | |

Refresh flow: find by hash → if `rotated_at` set ⇒ token reuse ⇒ revoke device (`token_reuse`);
if expired ⇒ revoke device (`inactive`); else mark `rotated_at`, insert new row, return new pair.

## otp_challenges

| Field | Type | Rules |
|---|---|---|
| id | uuid PK | |
| phone_e164 | text NOT NULL | |
| code_hmac | char(64) NOT NULL | HMAC-SHA256(pepper, phone ‖ code) |
| expires_at | timestamptz | created + 5 min |
| attempts | smallint DEFAULT 0 | max 5 |
| consumed_at | timestamptz NULL | |
| created_at | timestamptz | |

Index `(phone_e164, created_at DESC)`. Only the newest unconsumed challenge per phone is valid;
creating a new one marks older ones consumed. Rows older than 24 h are deleted by a cleanup job.

## contacts

| Field | Type | Rules |
|---|---|---|
| owner_id | uuid FK → users ON DELETE CASCADE | |
| contact_user_id | uuid FK → users ON DELETE CASCADE | ≠ owner_id |
| created_at | timestamptz | |

PK `(owner_id, contact_user_id)`. Only rows for matched accounts exist (FR-015).

## Redis keys (not persistent)

| Key | Purpose | TTL |
|---|---|---|
| `rl:otp:phone:{e164}:min` / `:hour` | request-code limits | 60 s / 1 h |
| `rl:otp:ip:{ip}` | request-code per-IP limit | 1 h |
| `rl:verify:ip:{ip}` | verify per-IP limit | 10 min |
| `rl:discover:{deviceId}` / `rl:lookup:{deviceId}` | contact limits | 1 h |
| `dev:status:{deviceId}` | cached `active`/`revoked` | 30 s |

## Client-side state

- **Android**: secure storage keys `refreshToken`, `deviceId`, `userId`; access token in memory.
- **Web**: refresh token in HttpOnly cookie; `deviceId`, `userId` in memory and `localStorage`
  (non-secret, used to show "this device" in the device list).
